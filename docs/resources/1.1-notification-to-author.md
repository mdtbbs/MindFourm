# 1.1 审核结果通知作者 - 实施完成

## 概述
当资源被管理员批准或拒绝时，系统会自动通知资源作者。

## 实现细节

### 后端修改

**文件：`src/modules/resources/resources.service.ts`**

1. 导入 `NotificationsService`：
```typescript
import { NotificationsService } from '../notifications/notifications.service';
```

2. 在构造函数中注入：
```typescript
constructor(
  // ... 其他依赖
  private notificationsService: NotificationsService,
  // ...
) {}
```

3. 在 `updateStatus` 方法中添加通知逻辑（第 642-673 行）：
```typescript
if (
  existingResource.status !== status
  && [RESOURCE_STATUS_APPROVED, RESOURCE_STATUS_REJECTED].includes(status as any)
) {
  // 管理员通知（已有）
  this.adminNotificationsService.publishModerationResult({
    item_type: 'resource',
    item_id: resource.id,
    action: status as 'approved' | 'rejected',
    actor_username: options.actorUsername || undefined,
    subject: resource.title,
    action_url: `/admin/resources?status=${status}`,
  }).catch((err) =>
    console.error('Admin resource moderation result notification error:', err),
  );

  // 通知资源作者（新增）
  const notificationContent = status === RESOURCE_STATUS_APPROVED
    ? `你的资源「${resource.title}」已通过审核`
    : `你的资源「${resource.title}」未通过审核${options.rejectReason ? '：' + options.rejectReason : ''}`;

  this.notificationsService.create({
    user_id: resource.user_id,
    type: 'system',
    content: notificationContent,
    emailEvent: 'system',
  }).catch((err) =>
    console.error('Resource author notification error:', err),
  );
}
```

## 通知内容

### 批准通知
```
你的资源「{资源标题}」已通过审核
```

### 拒绝通知
```
你的资源「{资源标题}」未通过审核：{拒绝理由}
```

如果没有提供拒绝理由，则不显示冒号后的内容。

## 通知类型
- **类型**：`system`（系统通知）
- **邮件通知**：启用（`emailEvent: 'system'`）
- **实时推送**：通过 SSE 推送给在线用户

## 验证步骤

1. **提交资源**：
   - 用户提交一个新资源
   - 资源状态为 `pending`

2. **管理员审核**：
   - 管理员在后台批准或拒绝资源
   - 如果拒绝，填写拒绝理由

3. **检查通知**：
   - 资源作者登录
   - 在通知列表中看到系统通知
   - 通知内容正确显示资源标题和审核结果
   - 如果拒绝，显示拒绝理由

4. **检查邮件**（如果启用）：
   - 作者收到邮件通知
   - 邮件内容与系统通知一致

5. **实时推送**：
   - 如果作者在线，通知实时显示
   - 无需刷新页面

## 技术要点

1. **异步处理**：通知发送是异步的，不会阻塞主流程
2. **错误处理**：通知失败只记录日志，不影响审核操作
3. **邮件配置**：遵循用户的邮件通知偏好设置
4. **缓存失效**：通知创建后自动清除未读通知缓存
5. **SSE 推送**：通知会通过 SSE 实时推送给在线用户
