# 资源社区中心设计

## 背景

MindFourm 已具备资源上传、外链、MindFileList 托管、分类、版本、审核、评分和管理后台能力。本次工作是在现有资源模块上做增量改进，将其完善为可持续维护的社区资源中心，不重做现有资源流程，也不改变既有 API 响应包装约定。

## 目标

- 让用户能够按类别、标签、Mindustry 版本和运行环境发现资源。
- 让作者和维护者能够维护多版本资源，并通过独立审核安全发布。
- 提供评分、无限层级评论、收藏、关注、相关推荐和失效报告。
- 提供资源所有权、维护者协作、统计和变更历史。
- 保持严格审核后的下载和外链访问边界。

## 范围外

- 不做兼容性投票或独立兼容性反馈，兼容问题通过评论和失效报告反馈。
- 不做作者维护公告。
- 不做版本差异对比。
- 不增加下载前确认弹窗。
- 不增加普通用户独立下载历史页面。
- 不改变 MindAuth、后端响应 envelope 或现有外部文件服务 API。

## 核心规则

### 访问权限

- 作者、维护者、版主和管理员可以查看自己有权限查看的资源详情、审核状态和拒绝原因。
- 下载本地文件、访问 MFL 文件或打开外链必须同时满足：资源公开、版本审核通过、版本未撤回、版本未被确认失效、资源未归档。
- 作者和工作人员不能通过下载接口绕过公开审核边界。
- “可能失效”只显示警告并保留下载；“已确认失效”停止对应资源或版本的下载/外链。
- 资源不可见时使用不可枚举的 404 行为。

### 分类、标签、版本和环境

- 现有 `ResourceCategory` 继续作为资源类别，支持父子分类。
- 资源只能选择末级分类；父分类用于导航、聚合和筛选。
- 标签由作者输入，空格自动拆分；标签支持中英文数字混合但内部不允许空格。
- 标签同一资源内去重，英文去重不区分大小写；标签参与搜索、筛选和相关推荐。
- 管理员可以重命名、合并、停用或屏蔽标签，操作不发送通知但写入审计日志。
- Mindustry 版本列表由管理员维护，支持正式版本顺序、特殊版本和停用；作者从启用列表选择。
- 版本兼容信息支持多个连续范围、多个离散版本和特殊版本混合选择；特殊版本不参与范围计算。
- 运行环境由管理员维护固定选项，资源主体和每个资源版本均可多选。
- 版本筛选匹配包含所选版本的兼容范围；同一筛选项内 OR，不同筛选项之间 AND。

### 资源主体和版本

资源主体包含或展示：标题、描述、类别路径、标签、Wiki、预览图片、维护状态、当前推荐版本摘要、统计摘要和评论入口。

每个资源版本包含：版本号、文件或外链、兼容版本、运行环境、可选更新日志、可选依赖、可选已知问题、兼容性说明、审核状态、撤回记录和下载统计。

- 兼容版本、运行环境和版本文件/外链是版本提交必填项。
- 更新日志、依赖、已知问题和兼容性说明可选，但表单提示作者填写更新日志。
- 依赖支持站内资源选择和纯文本依赖，并可填写依赖版本要求；站内资源不能依赖自身，禁止直接或间接循环依赖。
- 详情页的“前置依赖”和“被依赖资源”默认折叠，点击后按需加载，只展示当前版本的直接关系，不递归展示依赖树。
- 新版本独立审核；新版本审核期间旧的已通过版本继续可下载。
- 新版本审核通过后自动成为当前推荐版本，并同步资源主体的兼容版本、运行环境和展示摘要。
- 推荐版本撤回或确认失效后，自动回退到最近可用的已通过版本；没有可用版本时资源可展示但不可下载。
- 资源版本撤回需要填写原因。所有者、维护者、所属分类版主可立即撤回；管理员可撤回并可恢复。恢复后的版本必须重新进入待审核，不能直接公开。
- 版本提交、撤回、恢复、拒绝和审核操作保留完整审核历史。

### 资源状态和协作

- 资源所有者可以暂停维护、恢复维护、归档和恢复归档。
- 暂停维护保留展示和已通过版本下载，但关闭新版本提交。
- 归档资源从默认发现入口隐藏并停止公开访问，但保留详情和历史；所有者可自行恢复。
- 维护者可编辑资源说明、提交版本、编辑自己提交的待审核版本和撤回版本，但不能管理评论、转移所有权、恢复版本或管理其他维护者的版本。
- 所有者可以直接添加和移除维护者；变更立即生效并通知相关用户。
- 所有权转移需要接收方确认，支持所有者取消、接收方接受/拒绝和过期；转移后原所有者默认成为维护者，历史数据不变。

### Wiki、预览图片和封面

- Wiki 是资源级字段，允许 `http`/`https` 安全链接；修改 Wiki 不触发文件审核。
- 预览图片只属于资源主体，不绑定版本；复用现有站内图片上传能力。
- 作者和维护者可添加、排序、替换和删除预览图片，首张图片默认作为封面。
- 资源列表、搜索、相关推荐和作者资源统计可展示封面；无图片时使用占位图。
- 预览图片修改不触发文件审核，图片不计入版本下载统计。

### 评分和收藏关注

- 评分要求登录且手机号已验证，且资源公开并审核通过。
- 同一用户对同一资源只能保留一条评分；再次评分更新原记录，删除后可重新评分。
- 公开显示平均分、评分人数和 1 到 5 星分布；作者和维护者可查看统计。
- 用户可收藏或取消收藏资源；收藏记录在归档、暂停维护或可能失效时保留。
- 个人中心提供资源收藏列表，支持类别、标签、更新时间和收藏时间等筛选/排序；不增加独立下载历史页面。
- 用户可关注资源更新；取消关注立即停止后续资源更新通知和邮件，历史通知保留。

### 评论和回复

- 只有登录且手机号已验证的用户可发表评论、回复、点赞和点踩；公开资源的评论可匿名查看。
- 评论允许无限层级，使用 `parent_id` 保持父子关系；默认每个评论显示一条回复，其余折叠并按需加载。
- 支持基础 Markdown、站内图片和安全链接，原始 Markdown 最长 300 字符；渲染沿用现有 Markdown 清理逻辑。
- 图片复用现有站内上传能力，不允许评论插入外部图片；孤立上传文件由后续清理任务处理。
- 评论和回复支持点赞、点踩和取消；同一用户对同一条内容只能保留一种反应。
- 默认主评论按净赞数（赞数减踩数）降序；用户可切换最热、最新、最早。回复默认按热度，同热度按发布时间升序。
- 评论作者可以编辑自己的评论或回复；被举报、隐藏、删除或已有子回复后不可编辑。编辑后显示已编辑时间。
- 管理员或拥有资源板块管理权限的版主可隐藏、恢复、删除评论，不按资源作者或维护者授权。
- 删除评论保留节点和子回复，显示“该评论已删除”或“该回复已删除”；删除节点禁止新回复、编辑、互动和举报，已有子回复继续保留。
- 举报复用现有 reports 模块，支持原因和补充说明。同一用户不能重复举报同一内容；达到 `report_auto_hide_threshold` 后自动隐藏并通知管理员/资源版主和评论作者，最终由有权限人员处理。
- 评论回复、自动隐藏和审核结果发送站内通知；邮件按用户独立偏好控制。
- 评论和评分支持外站深链接：评分、评论、指定评论和指定回复可精确加载并定位；隐藏/删除节点按权限显示占位内容。

### 失效报告

失效报告使用独立资源失效报告状态，不复用 reports：

- 目标可以是资源或具体版本。
- 原因包括文件损坏、外链失效、无法下载、版本不兼容、内容不符和其他。
- 同一用户不能重复报告同一目标。
- 达到阈值自动标记“可能失效”，通知所有者和维护者；仍保留下载但显示警告。
- 版主或管理员确认后变为“已确认失效”，停止对应下载/外链。
- 作者或维护者提交修复后由版主/管理员标记已修复；误报可关闭并恢复访问。
- 资源级和版本级失效状态独立处理，保留完整处理记录。

### 发现、搜索和相关推荐

- 列表支持类别、标签、Mindustry 版本、运行环境、更新时间筛选。
- 支持热门、最新、评分、下载量排序。
- 搜索标题、描述、Wiki、更新日志和标签。
- 筛选条件同项 OR、跨项 AND；搜索关键词与筛选条件之间 AND。
- 相关推荐按同类别、共享标签、兼容版本交集和运行环境交集计算，评分、下载量和更新时间作为次级排序。
- 详情页底部最多显示 6 条相关推荐，并提供带筛选条件的“查看更多”。排除当前资源、删除、归档和已确认失效资源；可能失效资源可展示警告。
- 资源列表、搜索和相关推荐显示当前推荐版本的信息。

### 下载明细和统计

下载明细永久保留必要信息：用户、资源、版本、时间、来源和结果，不保存 IP、设备指纹或 Cookie。

- 普通用户无独立下载历史页面。
- 资源所有者可查看自己资源的下载用户明细；维护者只看汇总统计。
- 资源作者和维护者可查看评分平均值、评分分布、收藏数量、关注者数量和各版本下载量。
- 外链统计表示论坛侧点击，不表示外部站点实际完成下载。
- 资源所有权转移不删除历史数据；原所有者失去资源明细查看权限。

### 通知邮件偏好

站内通知始终发送，邮件按事件独立控制：

- 评论回复
- 资源更新
- 评论审核结果
- 所有权与维护者变更

邮件失败不影响站内通知和业务操作。举报者身份不暴露给评论作者。

## 分批实施

1. **基础模型与访问边界**：严格审核访问、Wiki、标签、版本/环境选项、末级分类、预览图片、资源状态和变更历史。
2. **版本生命周期**：版本字段、独立审核、推荐版本自动切换、撤回/恢复/回退、依赖关系和审核历史。
3. **社区互动**：评分规则、评论树、Markdown 图片、点赞点踩、编辑删除、举报自动隐藏和深链接。
4. **收藏关注与通知**：收藏列表、关注资源、站内通知、邮件偏好和资源更新通知。
5. **搜索发现**：筛选、排序、搜索字段、相关推荐和缓存。
6. **协作失效与统计**：维护者、所有权转移、失效报告、下载明细、作者统计、标签管理后台和管理队列。

每批独立执行后端类型检查、前端类型检查、构建、相关单元/集成测试和必要的 Playwright 场景，再单独提交。

## 验收重点

- 待审核、拒绝、撤回、归档和确认失效资源不能通过下载或外链接口绕过访问边界。
- 新版本审核期间旧推荐版本可用；通过后自动切换；撤回后正确回退。
- 资源主体列表只显示当前推荐版本兼容信息和运行环境。
- 父分类筛选包含后代末级分类，资源只能归属末级分类。
- 标签空格拆分、去重、搜索和管理员合并行为正确。
- 评论树按需加载，删除节点保留子回复，深链接可精确定位。
- 同一用户同一资源只有一条评分，评分和评论均受手机号验证约束。
- 失效报告自动标记、管理员通知和最终处理状态正确。
- 收藏、关注、通知、统计和所有权转移不丢失历史数据。
- 移动端详情、图片画廊、评论折叠和深链接无溢出或布局错乱。
