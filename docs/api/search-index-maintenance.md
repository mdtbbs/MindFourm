# Search index operations

The unified search uses allowlisted MySQL `FULLTEXT` indexes on source tables. InnoDB maintains each index as source rows are inserted, updated, or deleted; no application write hook or second document store is required. Search still combines `MATCH ... AGAINST` with escaped `%LIKE%` matching so substring searches remain available when the configured MySQL parser does not tokenize a phrase, particularly for Chinese text.

An administrator can inspect index definitions and recent operations with `GET /api/search/admin/indexes`. The response reports the MySQL version, source table engine and estimated row count, expected and actual columns, readiness (`ready`, `missing`, or `drift`), and the latest repair record.

To repair, reindex, or rebuild one index, send `POST /api/search/admin/indexes/{key}` with `{"action":"repair"}`, `{"action":"reindex"}`, or `{"action":"rebuild"}`. Keys come from the status response. Each operation processes one allowlisted source index, uses a MySQL connection-scoped advisory lock, writes a durable run record, and returns only after the DDL completes. Concurrent operations are rejected. Rebuilds may take time proportional to the selected source table; run them during a maintenance window for large tables.

The catalog covers topics and their published replies, users, public resources and published resource versions, parsed Mod content, forum/resource categories, tags, public game servers, official game versions, indexable developer feed entries, and published public knowledge articles. Query paths continue to apply publication, deletion, resource visibility, and viewer/block policy against source rows, including block exclusions for matching reply authors. Resource localization payload values are not indexed: `mod_localizations` stores locale progress and missing-key metadata, not translated string catalogs.

The catalog uses only `CHAR`, `VARCHAR`, and `TEXT` columns verified by the migration's `information_schema.columns` preflight. The production schema baseline is MySQL 5.7.44; the E2E CI service uses MySQL 8.4. The migration keeps the column sequence for every `MATCH(...)` expression and aborts before creating audit state if a source column is missing or non-text. This preflight plus the registered schema definitions is covered locally; a live 5.7.44 server is not available in the development worktree.

`GET /api/v1/search/suggestions?q=...` returns up to eight suggestions drawn only from the ten terms already exposed by the public popular-search list. It never reads personal search history. Prefix matches are preferred; if none exist, queries of at least four Unicode code points can match a public term at edit distance one. Unified search uses the first bounded suggestion only when exact results are empty and returns the suggested result with `suggested_query` so the UI can label the correction and retain an exact-search link.
